# Running the Factory locally: Orchestrator + Console

How to run the **LangGraph orchestrator** (`claude-software-factory/orchestrator/`)
and the **Factory Console** (`software-factory-view`) on your laptop — what to
configure, and which scripts to run.

## Prerequisites

| Tool | Needed by |
|---|---|
| Python 3.11+ | orchestrator |
| Node.js 20.19+ (pnpm via corepack) | Console, JS conformance harness |
| Docker Desktop | Console's Postgres + Redis; optional for the orchestrator |
| `git` | both |

---

## 1. The Orchestrator

```bash
cd claude-software-factory/orchestrator
make install      # runs scripts/install.sh: finds Python 3.11+, creates ./.venv,
                  # installs — works with pyenv/brew (no bare `pip` needed)
make test         # full test suite — confirms the checkout is healthy
make dev          # http://localhost:8080 (sqlite, auto-reload)
make smoke        # in another terminal: signed-webhook smoke test
```

All make targets and scripts use `./.venv` automatically once it exists.
With pyenv and no global version set, `make install` still works; to pick a
specific interpreter: `PYTHON=$(pyenv which python3.12) make install`.

**No configuration is needed for the first loop** — `make dev` boots with
safe placeholder credentials, so you can exercise webhook intake, the
idempotency ledger, `/healthz` and `/runs` immediately.

### Configuration (for the full loop)

Copy `config.local.env` values in place (used by `./deploy.sh`), or
`.env.example` → `.env` (used by `make dev` / compose). The variables that matter:

| Variable | What it is | Required? |
|---|---|---|
| `GITHUB_APP_ID` | your orchestrator GitHub App | for real GitHub events |
| `GITHUB_APP_PRIVATE_KEY_B64` | the App PEM, base64: `base64 -w0 < key.pem` | for real GitHub events |
| `GITHUB_WEBHOOK_SECRET` | the App's webhook secret | yes (default `dev-webhook-secret`) |
| `ANTHROPIC_API_KEY` **or** `CLAUDE_CODE_OAUTH_TOKEN` | credential for role runs | yes — or via the Console store below |
| `PUBLIC_BASE_URL` | where the service is reachable | default `http://localhost:8080` |
| `FACTORY_REPO` / `FACTORY_REF` | source of FACTORY.md + role prompts | defaults are fine |
| `FACTORY_LOCAL_PATH` | use your local factory checkout instead of cloning | optional, handy in dev |
| `CONSOLE_DATABASE_URL` / `CONSOLE_MASTER_KEY` / `CONSOLE_ORG` | read agent secrets the Console retained | optional (see §3) |

### Scripts

| Command | What it does |
|---|---|
| `make dev` | run on :8080 — sqlite, auto-reload, no Docker |
| `make smoke` | signed webhook accept / dedupe / bad-signature checks |
| `make test` / `make lint` / `make conformance` | test suites |
| `./deploy.sh local up` | full stack via docker compose (orchestrator + Postgres) |
| `./deploy.sh local logs` / `health` / `smoke` / `down` / `rebuild` | manage the compose stack |

### Receiving real GitHub webhooks on a laptop

GitHub can't reach `localhost`, so bridge with [smee.io](https://smee.io):
create a channel, set it as your GitHub App's webhook URL, then:

```bash
npx smee-client --url https://smee.io/<channel> --target http://localhost:8080/webhooks/github
```

Then claim a scratch repo by merging `.github/factory-orchestrator.json`
with `{"engine": "langgraph"}` (template in `templates/`), file a test
issue, and watch `curl localhost:8080/runs` and the labels move.

## 2. The Console (software-factory-view)

```bash
cd software-factory-view
./scripts/setup.sh    # one-time: checks toolchain, writes .env with a
                      # generated CONSOLE_MASTER_KEY, installs, builds,
                      # starts Postgres + Redis (Docker), migrates
./scripts/dev.sh      # API + worker + Vite dev server → http://localhost:5173
```

Alternative: `./scripts/start.sh` runs the full Docker stack (nginx + api +
worker + postgres + redis) on **http://localhost:8080**. `./scripts/stop.sh`
stops either mode.

### Configuration

`setup.sh` writes everything you need into `.env`:

| Variable | What it is | Required? |
|---|---|---|
| `CONSOLE_MASTER_KEY` | encrypts all stored secrets — **generated by setup.sh; back it up** | yes |
| `PUBLIC_ORIGIN` | how the browser reaches the Console (`:5173` dev, `:8080` docker) | handled by the scripts |
| `DEV_FAKE_LOGIN=1` | browse the UI without a GitHub App (dev only) | optional |
| `ANTHROPIC_API_KEY` | enables the "Ask the Factory" panel | optional |

The Console's **GitHub App is registered from its own `/setup` screen**
(manifest flow) — you don't edit App credentials into `.env`. Repos/orgs are
connected in the UI (Onboarding).

## 3. Wiring them together (Console-managed secrets)

Agent secrets entered in the Console (Settings → secrets, or the per-repo
onboarding step) — `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`,
`FACTORY_CROSS_REPO_TOKEN` — are written through to GitHub Actions **and
retained encrypted** in the Console's database. Point the orchestrator at
that store and you can stop putting the Anthropic key in its env at all:

```bash
# in the orchestrator's .env / config.local.env
CONSOLE_DATABASE_URL=postgres://console:console@localhost:5432/console
# (use the Console's DB_HOST_PORT/DB_PASSWORD values if you changed them)
CONSOLE_MASTER_KEY=<the same value as the Console's .env>
# CONSOLE_ORG=<org id>   # only if the Console hosts more than one org
```

Rules: env vars always win; the store fills what's unset; rotations in the
Console reach role runs on the next refresh (~15 min) without a restart.

## 4. A typical local session

```bash
# terminal 1 — Console
cd software-factory-view && ./scripts/dev.sh        # :5173

# terminal 2 — Orchestrator
cd claude-software-factory/orchestrator && make dev # :8080
# NOTE: the Console's DOCKER stack (./scripts/start.sh) also uses :8080.
# Run only one of them there — or move the orchestrator: PORT=8090 make dev

# terminal 3 — checks
cd claude-software-factory/orchestrator
make smoke                          # webhook intake works
curl -s localhost:8080/healthz      # {"status":"ok","engine":"langgraph"}
curl -s localhost:8080/runs         # run ledger
```

## Troubleshooting

- **Console: `PostgresError: role "console" does not exist`** — another
  Postgres on your machine (Homebrew, Postgres.app) owns :5432, so the
  migration hit it instead of the Console's Docker Postgres. Set
  `DB_HOST_PORT=5433` in the Console's `.env` and re-run
  `./scripts/setup.sh` — compose publishes on that port and the scripts
  follow. (`DB_PASSWORD` sets the compose Postgres password; user and
  database are fixed to `console`. A fully custom server goes in
  `DATABASE_URL`.)
- **Console start.sh: "Port 8080 is already in use"** — the orchestrator's
  `make dev` also defaults to :8080. Check with
  `lsof -nP -iTCP:8080 -sTCP:LISTEN`; then either run the orchestrator on
  another port (`PORT=8090 make dev`, smoke with
  `.venv/bin/python scripts/smoke.py http://localhost:8090`) or move the
  Console stack (`WEB_HOST_PORT=8081` in its `.env`).
- **Console URL loses its port** (`:8081/setup` → `http://localhost/setup/`,
  connection refused) — nginx built an absolute redirect from its own
  in-container port. Fixed in `infra/nginx.conf` (`absolute_redirect off`);
  rebuild with `./scripts/start.sh --rebuild`. Chrome caches 301s hard, so
  confirm with `curl -sSI http://localhost:8081/setup | grep -i location`
  and use a private window (or clear the site's cache) after rebuilding.
- **Console: "No .env — run ./scripts/setup.sh first"** — run setup once.
- **Orchestrator won't start: `GITHUB_APP_ID is required`** — running
  `factory-orchestrator` directly needs real env; use `make dev` (it has dev
  fallbacks) or fill `.env`.
- **Webhook returns 401** — the smoke/tunnel secret must match
  `GITHUB_WEBHOOK_SECRET` (dev default: `dev-webhook-secret`).
- **`CONSOLE_ORG` error** — the Console store holds secrets for several
  orgs; set `CONSOLE_ORG` to the one this orchestrator serves.
- **Nothing runs on your test repo** — its default branch needs
  `.github/factory-orchestrator.json` with `"engine": "langgraph"`;
  otherwise the orchestrator drops the event (Actions owns the repo).
